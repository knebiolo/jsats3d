Speed and modernization policy
-------------------------------
- Optimize inside existing legacy modules; do not add a parallel algorithm path.
- Safe improvements already used: modern pandas APIs, explicit timestamp units,
  SQLite composite indexes, vectorized metronome epoch assignment, vectorized
  child-window matching, and parallel neighbor search.
- Numerical safety fixes already used: explicit nanosecond timestamp conversion,
  SQLite-bound timestamp serialization, scalar/current scikit-learn DBSCAN eps,
  empty-chunk guards, and Deng discriminant validation before `sqrt`.
- The Deng discriminant guard records traceable no-solution rows for negative or
  invalid quadratic discriminants. It must not clamp negative values to zero or
  fabricate coordinates.
- Any optimization must be checked against the canonical 2019 row counts,
  intermediate-table counts, clock residuals, and final positions.
- Legacy KNN currently uses unseeded random chunk assignment; exact metric
  reproducibility requires a deliberate seed decision before changing that behavior.
- Never change pulse rates, timing windows, sound speed, DBSCAN eps, min_samples,
  receiver geometry, or rejection criteria solely for speed.
